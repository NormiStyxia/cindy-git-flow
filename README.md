# Git 流线

Cindy 左侧停靠 Git 面板。真实提交拓扑以流动折线展示，支持本地仓库与 Git worktree。

## 使用

1. 在 Cindy 导入 git-flow-1.7.0.cindy，启用插件。
2. 从插件页点「使用」，或在项目对话中说「用 Git 流线打开当前仓库」。
3. 点击面板右上角「＋」选择本机仓库。也可调用 git_open，传本机仓库绝对路径。
4. 「流线」显示最近 180 条提交；点放大镜展开搜索，点击记录看摘要与改动。点击或向上拖动「收起工具栏」只看流线，点击或向下拖动把手恢复。收起状态会记住；收起时点提交直接查看改动。
5. 「分支」列出本地、远端缓存，点击「比较」预览与当前 HEAD 的差距。
6. 「协作」显示同机 worktree，以及已接入服务的队友状态。

面板按 manifest 的 position: left 停靠主对话区左侧；可拖宽度、最小化或独立窗口（这些按钮由 Cindy 提供）。明暗主题沿用宿主，支持减少动态效果。需要本机已安装 Git；随包逻辑仅用 Node 标准库，安装后不下载依赖。

## 数据含义

仓库、远端和自动更新间隔使用跟随主题的自定义菜单，支持方向键、Enter/空格选择和 Esc 关闭。常驻顶栏只显示仓库、当前分支、改动数量和视图入口；点右上角「远端与显示」查看更新时间、跟踪分支、失败原因，调整自动更新和流光，或打开读图说明。更新异常时设置入口和收起把手会显示提示点。

- Git 读取约每 12 秒刷新，面板隐藏时暂停。仓库切换期间会重读一次并标注不稳定快照。
- 远端分支、待推送/待整合计数均基于本机缓存。默认每 5 分钟自动 fetch 所选远端；面板中可改为 1 或 10 分钟，也可关闭。面板隐藏时暂停，重新显示后检查是否到期；本地刷新不会重复触发获取。失败保留缓存并退避重试，手动成功获取重置定时。
- 手动与自动获取都只 fetch 所选远端，不 merge、pull、prune，不修改工作文件。
- 「上次成功更新」按仓库和远端分别保存，只在获取完成后更新；没有成功记录时显示「缓存文件更新于」，该文件时间可能受其他工具或失败获取影响。
- 获取时显示连接、下载百分比与已接收大小、整理记录和刷新视图。下载最长等待 14 分钟，HTTPS 连续 60 秒传输低于 1 KiB/s 时停止并退避重试；正常进度不会被旧版的 25 秒限制中断。超时会结束本次 Git 进程组。权限、地址解析、证书、连接中断和超时分别显示中文原因。
- 比较只说明提交关系和两端内容差异，不保证合并无冲突。插件没有切分支、合并、reset、提交或推送按钮。
- 提交作者不表示正在使用某个分支；同机 worktree 也不表示某人在线。
- 补丁超过 180,000 字符会截断并提示。极大补丁超出进程读取上限时返回失败，不会当成空改动。

## 中文提交说明

提交类型、模块和说明显示为中文，分支名、作者名、路径与代码标识保留原值。已知说明直接使用本地释义；新增英文说明经 Cindy 轻量任务模型批量翻译并缓存，生成期间保留提交标题并显示翻译进度，摘要和详情可展开原文。只发送提交标题，不发送代码或补丁，也不改写 Git 记录。

每批最多 20 条，去重后只翻译未缓存的内容；持久缓存最多 400 条；整份配置按 UTF-8 字节数控制在 60KiB 内，超过时仅淘汰最旧的译文，保留仓库和团队设置。失败时保留提交说明，单独显示原因并暂停自动调用，处理后可点「重试中文翻译」。没有可用模型时需在 Cindy 设置中配置轻量任务模型，模型选择由宿主与用户设置决定。

## 团队状态服务

随包 relay/server.cjs 是一个零依赖 Node.js 20+ 服务。它不会随插件安装而自动启动或公开到网络。团队部署一份即可，大家在插件设置中填写相同的服务地址和令牌。

    # GIT_FLOW_TOKEN 由部署环境设置，至少 24 字符随机令牌；不要提交到 Git。
    HOST=127.0.0.1 PORT=47831 node relay/server.cjs

在服务器上通过现有 HTTPS 反向代理将 /v1/presence 转发到此进程。不同团队使用不同实例/令牌。默认只监听回环地址；本机测试允许 HTTP 回环地址，跨机器必须 HTTPS。代理建议配置请求大小上限和频率限制。

1. 插件详情 → 设置：填写服务地址、自己的昵称、团队令牌。令牌经 /secrets 交由 Cindy 保存，不进配置文件、模型参数或广播频道。
2. 面板 → 协作：开启「共享当前仓库的状态」。每个仓库单独控制，默认关闭。
3. 使用同一 origin 的成员自动归到同一项目；使用不同 fork 时填写相同的「团队项目代号」。项目代号只是分组，访问隔离由团队服务令牌负责。
4. 每约 25 秒上传一份状态；失败会退避，最多间隔 120 秒。仅面板可见时更新。

上报字段：设备/工作区不透明 ID、昵称、分支名、HEAD、提交摘要、未提交数量、相对缓存上游的待推送数、采样时间。不会上传代码、文件名、本机路径、邮箱或 Git 凭证。昵称和分支来自客户端自报，不是 GitHub/GitLab 认证身份。

服务以接收时间判定在线：90 秒无心跳显示最后状态，24 小时后清理。服务只存内存，重启后由客户端下一次心跳恢复；关闭共享后旧状态按上述时限过期。一个实例上限 100 个项目、每项目 256 条工作区状态。

## 开发与验证

    node --test tests/*.test.cjs

源码仓库不包含生成的 `.cindy` 安装包。需要安装包时，在 Cindy 中使用插件打包工具 `ghost_forge_pack`，传入本源码目录的绝对路径；打包仅生成文件，不会自动安装或发布。

- ghost.json：权限、左侧停靠、工具声明。
- main.js / bridge.js：宿主消息、按请求去重、串行配置写入、面板通信。
- node/git.cjs / node/service.cjs / node/worker.cjs：本机 Git 数据读取及 JSON-RPC。
- graph.js / panel.*：提交布局和交互。
- node/team.cjs / relay/server.cjs：状态同步客户端、服务。
- settings.*：团队配置和安全令牌存储。

.dev/ 仅为作者本机浏览器验证夹具，Forge 不会打入插件包。真实宿主安装验证与浏览器夹具测试分别记录在 VALIDATION.md。
# 中文展示与读图

面板「怎么看？」解释提交标题、作者姓名、时间、颜色、云朵标签和按钮用途，并按当前图列出各颜色上出现的分支标签。颜色表示历史泳道，会复用；当前分支以绿色实心标签标记。提交作者姓名来自历史记录，不是平台认证账号或队友在线身份。

常见提交类型和已核对的英文说明显示中文释义，摘要和详情可展开原文；未知说明保留原文。分支名、作者名、文件路径及代码保留原值，不修改仓库记录。搜索同时匹配中文释义与原文。

### 流线显示范围

在「流线」右侧点「全仓库」可切换到「当前分支」。默认全仓库，重新打开面板或连接仓库时恢复默认。全仓库与当前分支分别读取最近 180 条真实提交；当前分支包括已合入的历史，不按作者筛选，也不会切换 Git 工作分支。游离状态显示「当前提交」，无首次提交的分支显示空状态。收起工具栏时保留所选范围，并在展开把手旁提示当前分支模式。定位其他分支时会按需要恢复全仓库显示。

## 跟随对话的项目（1.5.0）

默认跟随右侧对话：每次切换到项目对话，面板读取它的工作目录，显示对应 Git 仓库；工作目录在仓库子目录时会定位到仓库根目录。没有项目或 Git 读取失败时，清掉旧图并显示提示，仍可手动选择仓库。

手动切换仓库后，在当前对话中保留手动选择；未锁定时，下一次切换对话自动恢复跟随。左上角分支图标显示跟随状态，点击即可立即恢复并重新读取当前对话的项目。自动跟随不修改最近仓库列表和手动保存的仓库；手动选择仍会保存。

插件通过 Cindy 官方 session 订阅接收会话 ID 和工作目录，不读取对话消息。常驻逻辑仅保留最近一次前台通知，面板重新打开时可读取；刚安装、更新或逻辑重启后，如果宿主尚未发通知，先显示上次手动仓库并在图标提示中标明「等待对话切换」。切换一次对话后开始跟随。

旧远端获取可以继续完成并保存它自己的更新时间，但不会挡住新项目读取或覆盖新项目的状态。

范围是本机项目。事件协议目前只保证 sessionId/workdir，不保证携带远程标志；明确标记为远程、非绝对本机路径的通知不会读取。本机路径形式但未提供远程标志的事件仍按本机路径处理，因此不保证自动识别同路径的远程工作区；工具调用仍使用可信 session_context 检查本机/远程。

## 锁定仓库（1.6.0）

顶栏「＋」与刷新按钮之间的锁图标用于锁定当前仓库。亮起的闭锁表示已锁定，切换对话（包括未关联项目、无效项目）不改变当前仓库；本地刷新、远端更新和提交详情仍可使用。锁定状态与目标路径会保存，重开面板或重启插件后恢复。

锁定后仍可手动选其他仓库，锁定目标随手动选择更新。点击闭锁解锁，恢复跟随当前对话的最新项目；锁定期间左上角的跟随入口暂时不可用。没有成功读取仓库时不能新建锁定；如果保存的锁定路径已失效，可以手动换仓库或解锁。不同面板共享插件的同一份锁定设置。

## 后台模型用量记录（1.7.0）

插件不在面板显示统计。调用 `git_usage` 可以读取后台记录：提交标题翻译的调用次数、处理条数、输入/输出字符数，以及按字符估算的 token。Cindy 的 `oneshot_text` 接口目前不返回插件级真实 token，因此估算值不会冒充精确账单；如果宿主未来在响应中提供 token，插件会同时保存真实字段。

插件还旁听 Cindy 的 `did-turn-end` 元数据，记录宿主提供的对话轮次真实输入、输出和缓存 token。这部分是整轮对话用量，不等于 Git 流线插件自身用量；事件丢失时会标记记录不完整。
